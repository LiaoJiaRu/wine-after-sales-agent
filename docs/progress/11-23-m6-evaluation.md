## 2. 评测口径

1. 15 条用例由同一个 `pytest.mark.parametrize` 入口执行，参数 ID 严格为 U01-U15。
2. 每条用例均调用 `compile_graph().invoke()` 跑真实 LangGraph 主链，断言最终 State 的 `handoff`、`needs_human`，并按场景断言金额、错误码、证据状态或回复关键内容。
3. 常规场景使用确定性的 `IntentDecision` mock，避免外部 LLM 波动；**U08 例外**，改用真实 `router.route` 验证未成年人合规守卫，不伪造 `needs_human=True`。
4. U13/U14 通过 `monkeypatch` 替换 `app.graph.judge_draft`：U13 首次拒绝、第二次通过；U14 持续拒绝，验证首次加两次重试后转人工。
5. 评测时钟固定为 **2026-11-16 12:00:00+08:00**。`SO20261116001` 签收于 2026-11-15，因此证据齐全场景处于 7 天时效内，赔付期望为 1180 × 30% = 354.00 元。此处理只固定测试时钟，不修改业务时间逻辑。
6. `O-TIMEOUT` 订单与物流记录均已存在于 Mock 数据中，U07 直接进入超 7 天时效分支，无需额外补桩。
7. 订单、批次、政策、证据、赔付、草稿、SQLite、Redis 会话均走现有实现；Redis 使用 fakeredis，SQLite 与转人工队列使用 `tmp_path` 隔离。
